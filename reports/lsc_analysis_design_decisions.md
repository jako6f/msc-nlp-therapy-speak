# LSC Analysis Design Decisions

This document records consequential analysis-design decisions that should persist across notebooks. It is not a running implementation log; avoid obvious code-level details and record only decisions that affect interpretation, reproducibility, comparability, or downstream analysis.

## Decisions

| date | stage | decision | rationale | applies to | revisit if |
|---|---|---|---|---|---|
| 2026-06-02 | Shared LSC context preprocessing | Keep up to 3 mentions per document per analysis unit in the shared context table. | Reduces document-level dominance while preserving repeated-use signal and keeping downstream notebooks manageable. | Default shared mention table for Sentiment, Intensity, Severity/Intensifier, Breadth, and Thematic planning. | A later analysis requires uncapped mentions for a clearly justified diagnostic or sensitivity check. |
| 2026-06-02 | Shared LSC context preprocessing | Resolve overlapping raw-form matches within an analysis unit by keeping the longest span. | Prevents nested expressions such as `autism spectrum` from being counted both as `autism_spectrum` and `autism` at the same offset, while preserving raw-form diagnostics. | Mention-level shared context table and all downstream unit-year counts derived from it. | A later raw-form analysis needs intentionally nested target counts. |
| 2026-06-02 | Shared LSC context preprocessing | Collapse same-sentence acronym/expansion pairs within an analysis unit when they occur within a short local window. | Prevents constructions such as `attention deficit ... (ADHD)` and `autism spectrum ... (ASD)` from contributing two semantic contexts for one conceptual mention, while retaining `collapsed_raw_forms`, `collapsed_matched_texts`, and `collapsed_match_count` diagnostics. | Shared context table, raw-form diagnostics, manual samples, and all downstream semantic analyses using context rows. | A downstream analysis needs to treat acronym and expansion mentions as separate usage events. |
| 2026-06-02 | Shared LSC context preprocessing | Use `published_ts` as the primary semantic time source and define `lsc_year = published_year`; exclude rows with missing/unparseable publication dates or publication years outside 2014-2026 from the main shared context table. | Semantic-change analyses should date usage by document publication rather than crawl/capture year. The missing-date share is small enough to exclude, while pre-window pages crawled later would otherwise introduce survivorship-biased historical contexts. | Sentiment, Intensity, Severity/Intensifier, Breadth, Thematic analyses, and their shared unit-year diagnostics. | A later sensitivity analysis shows that excluded missing-date or pre-window rows materially change substantive conclusions. |
| 2026-06-02 | Sentiment | Lemmatise local collocate windows with spaCy `en_core_web_sm` before NRC-VAD matching. | Baes' sentiment method uses a lemmatised corpus; the small spaCy model is sufficient for short target windows and avoids a heavier dependency than needed. | Sentiment and the reusable VAD collocate handoff for Intensity. | Lemma errors or coverage diagnostics show systematic distortion for key target forms or baselines. |
| 2026-06-02 | Sentiment | Exclude only the focal mention's own target or baseline lexical material from its local VAD collocate window. | Cross-unit affective words are substantively meaningful collocates; for example, `frustration` should remain eligible around ADHD or Autism mentions even though it is also a baseline term. | Sentiment and the reusable VAD collocate handoff for Intensity. | Cross-unit terms visibly dominate trajectories and require a documented sensitivity analysis. |
| 2026-06-02 | Sentiment | Keep stopwords in the main NRC-VAD collocate index after removing target forms, punctuation, numerals, and one-character tokens. | Baes' sentiment/arousal collocate scripts do not show explicit stopword removal, so this maximises comparability. | Main Sentiment index and reusable VAD collocate table. | Function-word matches visibly dominate trajectories; then add a stopword-excluded sensitivity pass. |
| 2026-06-02 | Sentiment | Match NRC-VAD v2.1 greedily by multi-word expressions first, then unmatched unigrams. | NRC-VAD v2.1 includes rated multi-word expressions; matching them before unigrams uses the available resource without changing the local-window design. | Sentiment and Intensity VAD preprocessing. | MWE matches prove sparse or produce implausible high-impact contributors. |
| 2026-06-02 | Sentiment | Estimate annual uncertainty with document-level bootstrap confidence intervals. | Collocate observations are clustered by document; bootstrapping documents is more defensible than treating collocates as independent. | Annual Sentiment estimates and plots. | Runtime becomes prohibitive or a later modelling stage adopts a different uncertainty framework. |
| 2026-06-03 | Intensity | Compute the primary arousal index from the same reusable NRC-VAD collocate handoff used for Sentiment. | Arousal and valence are parallel VAD dimensions; freezing the collocate table prevents preprocessing drift between the two affective measures. | Primary Intensity arousal notebook and later integrated VAD comparisons. | The Sentiment handoff is rebuilt with changed tokenisation, exclusion, or matching rules. |
| 2026-06-03 | Breadth | Compute semantic breadth from local XL-LEXEME target-token embeddings with a configurable cap of 250 contexts per analysis-unit year for the current run. | XL-LEXEME is target-aware, so pooling the marked target tokens better matches the model objective than generic sentence pooling. The cap makes the current run tractable while preserving the same notebook path for larger or uncapped future data. | Primary Breadth notebook, saved embeddings, and Breadth diagnostics. | The local XL-LEXEME resource changes or future compute makes an uncapped run practical. |
| 2026-06-09 | Salience | Use source-year WARC-validated hits per million minimum-length WET tokens as the primary Salience series; retain candidate/WET rates, WARC-over-WET retention, raw-form composition, and publication-year status as diagnostics. | The completed trend run provides a consistent source-year WET token denominator, while validation and publication-year composition materially affect interpretation of crawl-slice prominence. | Primary Salience trajectories, comparator comparisons, and integrated synthesis. | A future trend handoff supports publication-year denominators or domain-level concentration estimates. |
| 2026-06-05 | Frame classification | Add a hierarchical substantive-discourse gate before clinical/lived-experience frame coding for ADHD and Autism target contexts only. | Many Common Crawl target mentions are boilerplate, list-like, generic, promotional, incidental, or noisy; masking these cases prevents them from becoming misleading negative examples for clinical/lived framing. | ADHD/Autism substantive-discourse rates, frame composition, frame-stratified LSC analyses, and integrated synthesis. | Validation shows the Stage-0 gate cannot be labelled reliably from target-centred passages. |
| 2026-06-08 | Frame classification | Use protected XLSX workbooks for human annotation, with immutable context fields stored explicitly as text and constrained label dropdowns. | Direct CSV editing in Excel converted passages beginning with formula-trigger characters into spreadsheet errors; protected XLSX handoffs preserve context text while remaining practical for one human annotator. | Human pilot and validation labels; clean labels remain machine-readable CSV outputs after ingestion. | A dedicated annotation tool replaces spreadsheet annotation. |
| 2026-06-04 | Frame classification | Use ACT-inspired LLM annotation and cross-model criticism, with human correction of critic-flagged labels. | The annotator-critic-human-correction workflow uses LLMs to scale annotation while preserving human adjudication for likely errors. | LLM training labels for the supervised frame classifier. | Critic flags are unmanageably frequent or validation performance remains weak after correction. |
| 2026-06-09 | Frame classification | Run the locked Codex annotator as sequential, isolated, schema-validated batches; use the pilot for prompt and reasoning calibration while preserving the human validation set for final evaluation only. | Fresh contexts prevent cross-batch dependence and context accumulation, while deterministic validation and preserved run metadata make LLM-assisted labels auditable. Keeping validation inaccessible prevents prompt/model-selection leakage. | Codex-assisted training labels, pilot calibration metrics, cross-model criticism, and final classifier evaluation. | Pilot performance is inadequate, operational usage limits make the workflow impractical, or a direct API workflow becomes methodologically preferable. |
| 2026-06-10 | Frame classification | Use codebook v0.4 as the final annotation contract, including explicit rules for category-set claims, concrete institutional provision, self-theorising symptom language, and legal/forensic mitigation. | Human review of Codex disagreements showed that list membership alone was sometimes overused as a non-substantive cue and that these discourse functions required explicit precedence rules. | Human validation, Codex annotation, cross-model criticism, classifier metadata, and downstream frame interpretation. | Further adjudication reveals a systematic contradiction or validation performance remains inadequate. |
| 2026-06-10 | Frame classification | Keep coding rules and boundary cases exclusively in the versioned codebook; restrict annotator and critic prompts to task order, evidence safeguards, validation checks, and output contracts. | Selectively duplicating codebook nuances in prompts creates redundancy and risks an incomplete or conflicting second annotation contract. | Human and LLM annotation consistency, prompt auditability, and future codebook revisions. | Pilot evidence shows that a narrowly scoped operational instruction cannot be expressed without prompt-level task clarification. |
| 2026-06-11 | Frame classification | Calibrate a cross-model critic on the adjudicated pilot, then use it to rank the 3,000 Codex labels for human correction; review up to 550 ranked cases and a separate random audit of 50 otherwise-unreviewed cases. | ACT motivates critic-guided correction but does not provide a universal review threshold. Pilot calibration, an adaptive low-yield stopping rule, and a residual audit make review effort explicit while checking both likely errors and critic misses. Critic suggestions remain advisory. | Corrected LLM-assisted classifier-training labels and an estimate of residual annotation error. | The selected critic recovers less than 60% of known pilot errors in its top 40 cases, shows a repeated systematic blind spot, or the residual audit indicates unacceptable unreviewed error. |
| 2026-06-11 | Frame classification | Preserve direct provenance from each append-only Codex annotation batch while splitting Claude criticism into chunks of at most 25 rows; stop on session/API errors without automatic retry and refuse silent rewrites of existing critic inputs. | The initial 75-row Claude pilot call generated more than 64,000 output tokens and exhausted the session before returning a structured result. Smaller chunks and bounded calls keep responses tractable, while source-batch provenance and explicit rebuilds preserve the audit trail and support future extensions. | Critic inputs, outputs, run metadata, and future annotation extensions. | Smaller chunks still exceed Claude output/session limits or a different criticism interface becomes methodologically preferable. |
| 2026-06-15 | Frame classification | Treat Claude Code as a critic-calibration interface, not the assumed production execution interface; use a full pilot to select low or medium effort, and require a budgeted API/batch or alternative critic interface if Claude Code limits prevent completing the pilot efficiently. | Corrected 25-row tests still required about 2.4 minutes and 9,990 output tokens at low effort, while high-effort tests required 6.7–18.3 minutes and 27,693–66,274 output tokens. Claude Code subscription limits stopped further calibration after only a few calls, making an uninterrupted 120-chunk production run operationally unrealistic. | Cross-model critic calibration and production execution planning. | Claude Code limits or model efficiency change enough to complete the full pilot and projected production run within a documented budget. |
| 2026-06-15 | Frame classification | Use Gemini 3 Flash Preview through the Gemini CLI as the production error-ranking critic, in independently partitioned ten-row chunks with restrictive tool policy, strict local validation, and human-only correction decisions. | The completed 200-row pilot validated all outputs and recovered 11 of 17 known Codex errors in the top 40 cases (64.7% recall; average precision 0.338), passing the predefined gate. Gemini suggested the correct replacement hierarchy for only 3 of 17 known errors, so its value is prioritising human review rather than automatic correction. Ten-row chunks avoided the field omissions and agent fallback observed with 25-row calls. | Gemini critic ranking, production criticism execution, and human correction workflow. | The preview model changes, production invalid-output or quota rates become impractical, or the residual human audit shows unacceptable critic misses. |
| 2026-06-05 | Frame classification | Train a hierarchical classifier with three logistic heads over shared sentence-transformer embeddings. | The substantive head uses all labelled examples, while clinical and lived-experience heads train only on substantive examples; this matches the codebook and avoids learning from masked non-substantive frame labels. | Full ADHD/Autism substantive/frame-label deployment, probabilities, frame weights, and downstream frame-aware analyses. | Held-out validation indicates insufficient Stage-0, conditional-axis, or derived-frame performance. |
| 2026-06-23 | Frame classification | Lock the current hierarchical logistic classifier rather than comparing additional model families. | The classifier is interpretable, matches the hierarchical codebook, and is adequate for a stratification layer; adding model search would over-weight classification relative to the main LSC analyses. | Classification reporting and all frame-aware downstream LSC analyses. | Held-out validation or downstream diagnostics show that frame errors materially change substantive conclusions. |

## What To Record

- Context-unit definitions and changes.
- Sampling caps, exclusion thresholds, or pooling rules.
- Aggregation levels for main analysis versus diagnostics.
- Criteria for creating a composite baseline.
- Model, lexicon, or resource choices with methodological consequences.
- Deviations from Baes et al. or from `reports/diachronic_lsc_analysis_plan.md`.

## What Not To Record

- Routine file naming.
- Ordinary plotting choices.
- Temporary debugging steps.
- Obvious notebook mechanics.
